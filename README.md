# ecoprof-merchant-feed

Ежедневный товарный фид Google Merchant Center для ecosmeticprof.com (Украина, украинский, UAH),
собранный по ТЗ клиента.

**Ссылка для Merchant Center:** https://enakoneschniy.github.io/ecoprof-merchant-feed/google_merchant_ua.xml

## Как это работает

- **Расписание.** GitHub Actions (`.github/workflows/feed.yml`) запускается каждый день в 03:17 UTC: это 05:17 по
  Киеву зимой и 06:17 летом. Ручной запуск: Actions → Merchant feed → Run workflow.
- **Сборка.** `update.sh` скачивает sitemap и все украинские карточки товаров. `extract.cjs` вытаскивает из них
  данные. `build.cjs` собирает XML и проверяет каждый товар.
- **Последняя корректная версия.** Она лежит в `site/google_merchant_ua.xml` и коммитится, когда меняется. Фид
  не публикуется, если:
  - найдена ошибка проверки;
  - число товаров упало больше чем на 20 %;
  - сайт не ответил.
  Тогда запуск падает, Google продолжает забирать прошлую версию, а GitHub присылает владельцу письмо о неудачном
  запуске.
- **Новый товар на сайте** сразу попадает в фид: тип, название и категорию Google скрипт подбирает сам.
  Открывается issue с меткой `feed-review`. Чтобы закрыть его, добавьте товар в `catalog-map.cjs`.
- **Новое дополнительное фото** не публикуется, пока его не проверили. Тоже открывается issue. Проверенное фото
  добавьте в `image-approved.json`. В `image-reject.json` идут:
  - фото «до/после»;
  - скриншоты отзывов;
  - инфографика с текстом.

Ручные данные, которых нет на сайте, лежат в `catalog-map.cjs`:
- тип товара и название для заголовка;
- `product_type`;
- категория Google;
- исключённые SKU;
- объёмы, которые на странице скрыты.

Решения по бренду и `custom_label_0`:
- линейка AV&eco.prof.cosmetics → «Товари партнерів»;
- остальное → «Основна лінійка».

## Локально

```bash
npm ci
npm run update   # результат: site/google_merchant_ua.xml, отчёт: out/google_merchant_ua.report.json
```

Коды выхода `build.cjs`: `2` — ошибка проверки, `3` — число SKU упало больше допустимого. В обоих случаях
прошлый файл не трогается.

## Когда это перестанет быть нужным

Генератор читает вёрстку текущего сайта на OpenCart. Когда его заменит новый магазин, сборка начнёт падать
(вы получите письма). Тогда фид должен отдавать сам новый магазин.
